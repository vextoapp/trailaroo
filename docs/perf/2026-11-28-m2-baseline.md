# M2 performance baseline (28 Nov 2026)

Measured before any M2 feature lands, so every later M2 PR can be compared against it. Targets are from SPEC: Lighthouse 95+ on a mid-range Android over throttled 4G, and under 200 KB of JavaScript on first load, excluding MapLibre.

## Results

Median of 3 runs per page (by performance score), after the one fix in this PR (see below).

| Page | Performance | Accessibility | Best practices | SEO | LCP | TBT | CLS | First-load JS (excl. MapLibre) |
|---|---|---|---|---|---|---|---|---|
| Home `/` | **79** | 100 | 100 | 100 | **5.6 s** | 20 ms | 0 | 184 KB |
| Explore `/explore` | 100 | 100 | 100 | 100 | 1.2 s | 10 ms | 0 | 184 KB |
| Trail `/trails/black-mountain-summit-walk-11325858` | 100 | 100 | 96* | 100 | 0.8 s | 50 ms | 0 | 188 KB |

Bold means under target. *Local-only, see "Not real" below.

Before the fix, the trail page scored 97 for performance with **CLS 0.104** (target is under 0.1).

## What's under target, and why

- **Home LCP 5.6 s (performance 79).** The hero and the four mood photos are full-size JPEGs of 96 to 211 KB each, served as-is to phones. Lighthouse estimates about 80% of their bytes are wasted at phone size. The fix is smaller variants (for example 640 px and 1280 px, in WebP or AVIF) with `srcset`, made by the asset sync step. This is not done here, because it's an image pipeline change, not a quick fix.
- **First-load JS is 184 to 188 KB against a 200 KB budget.** That leaves only 12 to 16 KB of headroom, before M2 adds search, filters, weather and alerts. The design already says the place list, weather and alerts load after first paint; every M2 PR should check this number.

## Fixed in this PR

- **Trail page layout shift (CLS 0.104 to 0).** The "New here?" strip was decided in the browser after load, and it pushed the trail down for first-time visitors. It's now rendered on the server and hidden before first paint for returning visitors.

## Not real (local-only)

- **Trail page best practices 96.** The console errors are the map's tile requests to `tiles.trailaroo.com` failing from `localhost`, because the tile bucket only allows our own sites. They don't happen on trailaroo.com.

## Method

- Lighthouse 13.6.0 CLI, default mobile config: Moto G Power emulation, simulated slow 4G and 4× CPU slowdown. Categories: performance, accessibility, best practices, SEO.
- Production build (`pnpm build && pnpm start`) on a MacBook, Chrome for Testing (Playwright's Chromium 1255), headless.
- 3 runs per page; the table shows the median run by performance score.
- **First-load JS** is the sum of `transferSize` (compressed) of every `Script` request in the report's network requests. The MapLibre chunk (about 290 KB, which loads with the map on the trail page) is subtracted. Explore's list view doesn't load the map on a phone.
- **No PWA score.** Lighthouse dropped the PWA category in version 12, so SPEC's "Lighthouse PWA ... score of 95 or more" can't be measured as written. The wording needs updating, for example to "installable, with a working offline page, checked by the offline e2e test". That change is flagged here, not made.

To repeat this: run the production build on a free port, then for each page:

```bash
npx lighthouse@13.6.0 http://localhost:3200/ --only-categories=performance,accessibility,best-practices,seo --output=json --output-path=home-1.json --chrome-flags="--headless=new"
```
