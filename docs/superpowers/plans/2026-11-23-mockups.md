# Mock-ups and project CLAUDE.md Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clickable static HTML mock-ups of six screens (mobile + desktop, dark + light) that become Open Trails' design reference, plus the project CLAUDE.md additions.

**Architecture:** Plain HTML pages sharing one `tokens.css`, one `mockups.css` and one `mockups.js`. Each screen is a single responsive page; `index.html` frames every screen at 390 px and 1280 px in iframes. A dependency-free Node script (`check.mjs`) guards contrast, external calls and broken links.

**Tech Stack:** HTML, CSS custom properties, vanilla JS (ES modules), inline SVG, Node 24 for the check script. No packages.

**Spec:** `docs/superpowers/specs/2026-11-23-mockups-design.md` (and `docs/SPEC.md` > Design system and UX, Activities, Feature inventory).

## Global Constraints

- No app code; nothing outside `docs/`, `CLAUDE.md`.
- No third-party requests: no external `<script src>`, `<link href>`, `@import`, `url(http…)`, `<iframe src=http…>`, `<img src=http…>`. Plain `<a href>` to official sources (NPWS, RFS, ESA, OSM) is allowed.
- WCAG 2.2 AA: text contrast ≥ 4.5:1 (≥ 3:1 for ≥ 24 px or bold ≥ 18.66 px and for UI borders/icons); touch targets ≥ 44 px; visible focus; respects `prefers-reduced-motion`.
- Difficulty = colour + shape + word: Easy green ●, Moderate amber ▲, Hard red ◆, Very hard black ■ (white outline in dark mode).
- Every map has a text/list alternative and the attribution line "© OpenStreetMap contributors · Protomaps · Mapterhorn".
- Safety info (fire danger, alerts) always shows source and time, e.g. "NSW RFS · updated 9:30 am".
- App name only via `data-app-name` filled from one constant `APP_NAME = "Open Trails"` in `mockups.js`.
- en-AU spelling and units (km, m, min/km).
- No upsells, badges-for-engagement or paywall language.
- Bottom tabs (mobile): Explore, Saved, Record (centre), Activity, You. Desktop: left sidebar, same order.
- Ask the user before downloading font files, committing, and pushing. Work on `main`.

## Review Focus

1. 320 px width and 200 % text zoom: no horizontal scroll, tab bar labels don't overlap → `check.mjs` can't see this; Task 8 browser pass at 320 px.
2. Keyboard only: every clickable thing reachable with Tab, Enter/Space works, focus visible, Escape closes sheets → Task 3 adds `keyboard` checks to the shared JS; Task 8 walks each screen.
3. Theme set to "system" then OS theme flips while the page is open → Task 3 `mockups.js` listens to `matchMedia` change; Task 8 verifies with the browser colour-scheme emulation.
4. Screen reader on a map: map SVG has `role="img"` + `aria-label`, and a "List" / "Text version" toggle exists → `check.mjs` asserts every `.map` has an `aria-label` and a sibling `[data-text-version]`.
5. Gallery iframes in the opposite theme to the gallery: theme choice propagates to every iframe → Task 3 uses `postMessage`; Task 8 verifies.
